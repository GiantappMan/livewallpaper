# 更新与发布

应用支持两条更新链路和一条本地发布链路：

| 链路 | 内容 | 检查地址 | 用户控制 |
|---|---|---|---|
| 界面热更新 | 前端界面（zip 包，无需升级程序） | 「热更新地址」（ui.json） | 设置 → 软件更新：开关、还原内置界面 |
| 程序更新 | 整个应用（NSIS 安装包） | 「更新服务器地址」（stable.json / preview.json） | 设置 → 软件更新：通道、自动下载、确认安装 |
| 本地发布 | 开发者把产物推到自己的 Cloudflare | —— | `bun run scripts/publish.ts` |

## 一、界面热更新

- **内置界面**：随安装包分发（Tauri `frontendDist`），是永久的兜底——热更新目录缺失或损坏时主窗口自动回退，永不白屏。
- **热更新界面**：数据目录 `ui/`（`index.html` + 资源 + `ui.json` 清单），经 `ui://` 协议（`http://ui.localhost/`）加载；生效时优先于皮肤接管主窗口（`skin::main_window_target` 最前面判断）。
- **检查与应用**：配置了地址且开启「启动时自动更新界面」时，启动后台拉取 `ui.json`，远程版本更新则下载 zip、原子换装（staging → 备份 → 替换）、置生效标记并原地刷新主窗口（进度经 `ui-update-event` 广播）。
- **还原机制**：设置 → 软件更新 → 「还原内置界面」删除 `ui/` 并清除生效标记，立即回到随程序分发的内置界面；自动更新开关保持不变（保持开启则下次启动会重新检查应用）。
- 手动流程：「检查更新」→ 显示新版本 → 「下载并应用」；无条件重下（不比较本地版本）。

### ui.json 清单格式

```json
{
  "version": "4.0.2",
  "url": "https://<worker>.workers.dev/ui/ui-4.0.2.zip",
  "notes": "更新说明（应用内展示）",
  "date": "2026.10.5"
}
```

`url` 也可以是相对地址（以清单地址为 base 解析）。zip 包内容为前端 `dist/` 的内容（`index.html` 在 zip 根），缺入口文件会被拒装；解压带 zip-slip 防护。

## 二、程序更新

- **通道**：`stable`（正式版，忽略预发布版本）/ `preview`（预览版，alpha 等都收）/ `off`（关闭检查）。
- **自动下载**：开启后启动检查发现新版本即自动下载安装包到数据目录 `update/`；**安装始终需要用户确认**——下载完成后界面弹持久提示（可「安装并重启」或「暂不安装」），暂不安装可稍后在设置页继续。
- **版本比较**：宽松 semver（`4.0.1-alpha.3 < 4.0.1`），只有远程版本更新才提示。
- **安装**：写批处理（等待安装器静默完成 → 重启应用）后分离进程执行，应用走托盘退出语义退出；perMachine 安装器触发 UAC 提权。

### 通道清单格式（`<base>/stable.json`、`<base>/preview.json`）

```json
{
  "version": "4.0.2",
  "url": "https://<worker>.workers.dev/dl/GiantappWallpaper_4.0.2_x64-setup.exe",
  "notes": "更新说明",
  "date": "2026.10.5",
  "prerelease": false
}
```

## 三、本地发布（Cloudflare 渠道）

发布 = Worker + R2 桶：Worker 只读地对外提供 R2 对象（清单/安装包/界面 zip）。

### 首次准备

1. 确认 Cloudflare 账号已开通 Workers 与 R2（免费额度即可）。
2. 登录（只需一次，凭据存本机，不入仓库；脚本固定使用 wrangler@4）：

   ```bash
   bunx wrangler@4 login
   ```

   未登录时运行发布脚本会提示这条命令并退出；也可用 `CLOUDFLARE_API_TOKEN` 环境变量。

### 发布

```bash
# 正式版（版本号不允许带 - 后缀）：构建 → 上传安装包 → 写 stable.json → 更新 ui.json
bun run scripts/publish.ts release --notes "本次更新内容"

# 预览版（alpha 版本发 preview 通道）
bun run scripts/publish.ts preview --notes "..."

# 只更新界面热更新包（不构建安装包、不动程序通道）
bun run scripts/publish.ts release --ui-only --skip-build --notes "..."

# 复用上次构建产物
bun run scripts/publish.ts release --skip-build

# 正式版同步覆盖 preview.json（预览用户也能收到该正式版）
bun run scripts/publish.ts release --sync-preview
```

脚本每次幂等执行：部署 Worker（首次发布即完成安装）→ 确保 R2 桶存在 → 构建 → 打包 UI zip（bsdtar，回退 Compress-Archive）→ 上传全部对象 → 打印接入地址。R2 对象布局：

```
stable.json  preview.json  ui.json
dl/GiantappWallpaper_<version>_x64-setup.exe
ui/ui-<version>.zip
```

> **网络提示**：`*.workers.dev` 在部分网络环境（含境内多数网络）不可达。若应用侧无法访问，可在 Cloudflare 控制台为 Worker 绑定自定义域名，然后发布时用环境变量指定对外地址：
>
> ```bash
> CF_WORKER_URL=https://updates.example.com bun run scripts/publish.ts release
> ```
>
> 清单里的下载地址由该 URL 生成；更换域名后需要重新发布一次清单。

### 应用侧接入

二选一：

1. 应用内 设置 → 软件更新，把脚本输出的地址填入「热更新地址」和「更新服务器地址」；
2. 打包时内置默认值（用户无需手动配置，之后仍可在设置里覆盖）：

   ```bash
   GIANTAPP_UPDATE_URL=https://<worker>.workers.dev \
   GIANTAPP_UI_UPDATE_URL=https://<worker>.workers.dev/ui.json \
   bun run build
   ```

   只有数据目录 `configs/update.json` 不存在（全新安装）时才注入默认值，避免覆盖用户的有意清空。

### 安全约定

- 仓库不保存任何 Cloudflare 凭据；账号绑定来自本机 `wrangler login` 的 OAuth 登录态。`.gitignore` 已忽略 `wrangler.generated.toml`（脚本按 `CF_WORKER_NAME` / `CF_R2_BUCKET` 生成）、`.wrangler/` 与 `build/publish/`。
- Worker 只开放 GET/HEAD；发布操作全部走开发者本机。
- 应用校验更新地址：仅 http/https；release 构建拒绝 localhost、环回、私有与保留地址（debug 构建放行，便于 `wrangler dev` 联调）。
