# 更新与发布

应用支持两条更新链路和一条本地发布链路：

| 链路 | 内容 | 检查地址 | 用户控制 |
|---|---|---|---|
| 界面热更新 | 前端界面（zip 包，无需升级程序） | 「热更新地址」，留空自动跟随更新通道 | 设置 → 软件更新：开关、还原内置界面 |
| 程序更新 | 整个应用（NSIS 安装包） | 「更新服务器地址」（stable.json / preview.json） | 设置 → 软件更新：通道、自动下载、确认安装 |
| 本地发布 | 开发者把产物推到自己的 Cloudflare | —— | `bun run scripts/publish.ts` |

## 一、界面热更新

- **内置界面**：随安装包分发（Tauri `frontendDist`），是永久的兜底——热更新目录缺失或损坏时主窗口自动回退，永不白屏。
- **热更新界面**：数据目录 `ui/`（`index.html` + 资源 + `ui.json` 清单），经 `ui://` 协议（`http://ui.localhost/`）加载；生效时优先于皮肤接管主窗口（`skin::main_window_target` 最前面判断）。
- **检查与应用**：开启「启动时自动更新界面」且有可用清单地址时，启动后台拉取清单，远程版本更新则下载 zip、原子换装（staging → 备份 → 替换）、置生效标记并原地刷新主窗口（进度经 `ui-update-event` 广播）。
- **地址解析**：自定义「热更新地址」优先；**留空则跟随程序更新通道**——正式版拉 `<更新服务器地址>/ui/stable.json`，预览版拉 `<更新服务器地址>/ui/preview.json`（通道选「关闭」时不检查）。**注意：界面热更新层生效时会盖住整个皮肤系统（皮肤切换失效）**，因此发布脚本默认**不发**界面热更新包，仅在全量换新界面时用 `--with-ui` / `--ui-only` 显式发布；不发布时清单保持 `0.0.0` 占位（永不生效）。
- **版本缓存与手动切换**：每次应用的界面包都会存入数据目录 `ui-versions/<版本>/`（保留最近 5 个，超出自动裁最旧的，当前生效版本不裁）；设置页「界面版本」下拉可列出内置界面与全部本地缓存版本并手动切换，切换热更新版本立即生效，选「内置界面」等同还原。
- **还原机制**：设置 → 软件更新 → 「还原内置界面」删除 `ui/` 并清除生效标记，立即回到随程序分发的内置界面（**已下载的版本缓存保留**，可从「界面版本」下拉再次选择）；自动更新开关保持不变（保持开启则下次启动会重新检查应用）。
- **停用提示**：「启动时自动更新界面」关闭时，状态行明确显示「已停用热更新；当前使用××」，当前生效的界面不受影响。
- 手动流程：「检查更新」→ 显示新版本 → 「下载并应用」；无条件重下（不比较本地版本）。

### 界面热更新清单格式（`ui/<通道>.json`，发布时只写入所选通道）

```json
{
  "version": "4.0.2",
  "url": "https://releases.giantapp.cc/wallpaper/ui/ui-4.0.2.zip",
  "notes": "更新说明（应用内展示）",
  "date": "2026.10.5"
}
```

`url` 也可以是相对地址（以清单地址为 base 解析）。zip 包内容为 **Fluent 皮肤构建产物**（`examples/skin-fluent`，app 型完整前端，`index.html` 在 zip 根；`ui://` 协议同权提供 `/_sdk/client.js`），缺入口文件会被拒装；解压带 zip-slip 防护。内置界面 dist 不作为热更新内容——它随安装包内置，并经 build.rs 以「巨应3 怀旧」皮肤分发。

## 二、程序更新

- **通道**：`stable`（正式版，忽略预发布版本）/ `preview`（预览版，alpha 等都收）/ `off`（关闭检查）。
- **自动下载**：开启后启动检查发现新版本即自动下载安装包到数据目录 `update/`；**安装始终需要用户确认**——下载完成后界面弹持久提示（可「安装并重启」或「暂不安装」），暂不安装可稍后在设置页继续。
- **版本比较**：宽松 semver（`4.0.1-alpha.3 < 4.0.1`），只有远程版本更新才提示。
- **安装**：写批处理（等待安装器静默完成 → 重启应用）后分离进程执行，应用走托盘退出语义退出；perMachine 安装器触发 UAC 提权。

### 通道清单格式（`<base>/stable.json`、`<base>/preview.json`）

```json
{
  "version": "4.0.2",
  "url": "https://releases.giantapp.cc/wallpaper/dl/GiantappWallpaper_4.0.2_x64-setup.exe",
  "notes": "更新说明",
  "date": "2026.10.5",
  "prerelease": false
}
```

## 三、本地发布（Cloudflare 渠道）

发布 = R2 桶直连：桶开启公开访问后对外只读提供对象（清单/安装包/界面 zip），无 Worker、无服务端代码。当前对外地址是自定义域 **`https://releases.giantapp.cc`**（已绑桶 `giantapp-releases`；桶的 r2.dev 公开地址 `https://pub-4bf6dc007b014347bd8e5c35338cfca9.r2.dev` 同时保留作备用）。

**多产品共用渠道（2026-10-10 起）**：统一用桶 `giantapp-releases`，每个产品一个顶层前缀——壁纸的所有对象都在 `wallpaper/` 下，收藏猿在 `favape/` 下，新增产品往新前缀传清单即可。同日启用直连方案后，两个旧 Worker（`giantapp-wallpaper-releases`、`giantapp-releases`）均已删除——**「更新服务器地址」还指向旧 Worker 域名的存量客户端需要在 设置 → 软件更新 手动改成新地址**（应用无法自救：清单 base 本身就配在旧域名上）。

### 首次准备

1. 确认 Cloudflare 账号已开通 R2（免费额度即可）。
2. 登录（只需一次，凭据存本机，不入仓库；脚本固定使用 wrangler@4）：

   ```bash
   bunx wrangler@4 login
   ```

   未登录时运行发布脚本会提示这条命令并退出；也可用 `CLOUDFLARE_API_TOKEN` 环境变量。

### 发布

```bash
# 正式版（版本号不允许带 - 后缀）：构建 → 上传安装包 → 写 stable.json + ui/stable.json（严格单通道）
bun run scripts/publish.ts release --notes "本次更新内容"

# 预览版（alpha 版本发 preview 通道）
bun run scripts/publish.ts preview --notes "..."

# 只更新界面热更新包（不构建安装包、不动程序通道；会盖住皮肤系统，慎用）
bun run scripts/publish.ts release --ui-only --skip-build --notes "..."

# 复用上次构建产物
bun run scripts/publish.ts release --skip-build

# 正式版同步覆盖 preview.json（预览用户也能收到该正式版）
bun run scripts/publish.ts release --sync-preview   # 同时覆盖预览通道的程序清单
```

脚本每次幂等执行：确保 R2 桶存在并开启 r2.dev 公开访问（首次发布即完成安装）→ 构建 → 上传对象（清单 `no-cache`、大文件缓存 1 小时）→ 打印接入地址。R2 对象布局（都在 `wallpaper/` 产品前缀下；`ui/` 界面热更新对象仅 `--ui-only` / `--with-ui` 时写入）：

```
wallpaper/stable.json  wallpaper/preview.json            程序更新清单（只写所选通道）
wallpaper/dl/GiantappWallpaper_<version>_x64-setup.exe
wallpaper/ui/stable.json  wallpaper/ui/preview.json      界面热更新清单（默认不写，占位 0.0.0）
wallpaper/ui/ui-<version>.zip                            界面热更新包（Fluent 皮肤构建产物）
```

**官网 / 壁纸服务端的下载地址**：直连方案没有固定「最新版」302 入口（原 `dl/latest` 随 Worker 一起移除）。两个选法：

- 推荐：服务端拉 `https://releases.giantapp.cc/wallpaper/stable.json`，取 `url` 字段做 302——仍是配置一次，且永远指向当前正式版；
- 简单：下载按钮直接指向清单里当前版本的安装包地址（`wallpaper/dl/GiantappWallpaper_<版本>_x64-setup.exe`），每次发版同步更新。

壁纸服务端（giantapp-wallpaper-server）如用环境变量配置下载地址（`NEXT_PUBLIC_DIRECT_DOWNLOAD_URL` / `NEXT_PUBLIC_PREVIEW_DOWNLOAD_URL`），注意 `NEXT_PUBLIC_*` 是 Next.js 构建期内联，改完需要重新构建部署站点才生效。

> **对外地址说明**：脚本默认输出桶的 r2.dev 地址（`*.r2.dev` 在部分网络环境不可达且有平台限速）。当前已绑定自定义域 `releases.giantapp.cc`，**发布时必须带上覆盖变量**，让清单里的下载地址走自定义域：
>
> ```bash
> CF_R2_PUBLIC_URL=https://releases.giantapp.cc bun run scripts/publish.ts release
> ```
>
> `CF_R2_PUBLIC_URL` 是桶根地址，产品前缀由脚本拼接。换域名后重新发布一次清单，安装包下载即切到新域名；但客户端「更新服务器地址」（清单 base）仍指向旧地址，需要用户手动改一次才彻底离开旧域名。

### 应用侧接入

二选一：

1. 应用内 设置 → 软件更新，把脚本输出的「对外地址 + `/wallpaper`」填入「更新服务器地址」即可——**「热更新地址」留空**，界面更新自动跟随更新通道（正式版用户拿 `wallpaper/ui/stable.json`，预览版用户拿 `wallpaper/ui/preview.json`）；需要单独指定界面源时才填「热更新地址」；
2. 打包时内置默认值（用户无需手动配置，之后仍可在设置里覆盖）：

   ```bash
   GIANTAPP_UPDATE_URL=https://releases.giantapp.cc/wallpaper \
   bun run build
   ```

   只有数据目录 `configs/update.json` 不存在（全新安装）时才注入默认值，避免覆盖用户的有意清空。`GIANTAPP_UI_UPDATE_URL` 仍支持（内置自定义热更新地址，优先于通道跟随；手动指定时指向 `ui/stable.json` 或 `ui/preview.json`），一般不需要。

### 安全约定

- 仓库不保存任何 Cloudflare 凭据；账号绑定来自本机 `wrangler login` 的 OAuth 登录态。`.gitignore` 已忽略 `.wrangler/` 与 `build/publish/`。
- R2 公开访问是只读的（r2.dev 仅 GET/HEAD）；发布操作全部走开发者本机。
- 应用校验更新地址：仅 http/https；release 构建拒绝 localhost、环回、私有与保留地址（debug 构建放行，便于本地联调）。
