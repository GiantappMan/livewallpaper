# 开发

## 环境要求

- Rust（stable，含 MSVC 工具链）
- [Bun](https://bun.sh) ≥ 1.2（也兼容 pnpm/npm，仓库脚本以 bun 为准）
- WebView2 Runtime（Win11 自带；Win10 若无，安装器会自动下载）

## 本地开发流程

```bash
# 0. 首次：安装依赖（根目录 workspace，一条命令装完）
bun install

# 1. 一键启动调试（根目录执行）
bun dev
```

`bun dev` = `tauri dev`：自动起 Vite（localhost:5173）→ 增量编译 Rust → 运行应用；
Rust 或前端代码改动会自动重建/热更新。

> 调试工具：debug 构建内置 WebView2 DevTools，应用窗口内右键 → "检查"（或 F12）
> 可看 console/network；`window.__TAURI_INTERNALS__` 可在控制台直接调 invoke。
> Rust 断点：VS Code / RustRover 附加到 `giantapp-wallpaper.exe` 即可。

> 不放 mpv 也能跑：视频/动图壁纸会自动使用应用内嵌 WebView 播放器（对应 v3 的
> System Player），webp/gif 由浏览器内核直接渲染。

### 放置 mpv（推荐，视频壁纸性能更好）

下载 <https://mpv.io/> 解压，放到 `src-tauri/assets/players/mpv/mpv.exe`
（`compile.ps1` 打包时会自动下载，开发时可手动放置）。

## 常用命令（均在根目录）

| 命令 | 作用 |
|---|---|
| `bun dev` | 完整应用调试（Vite + Rust + 应用） |
| `bun run dev:ui` | 仅前端（浏览器打开，API 优雅降级） |
| `bun run check` | cargo check |
| `bun run test` | 引擎单元测试 |
| `bun run build` | 前端构建 + release + NSIS 安装包 |

## 发布

```powershell
# 方式一：根目录一键
bun run build

# 方式二：脚本（含 mpv 自动下载）
cd src/build
./compile.ps1
```

产物：`src/build/dist/GiantappWallpaper_4.x.x_x64-setup.exe`

### NSIS 工具链下载超时（国内网络）

`tauri build` 首次打包会自动下载 NSIS 工具链到 `%LOCALAPPDATA%/tauri/NSIS`。
若 CLI 下载超时（`timeout: global`），用 curl 手动放置即可（curl 走同样的源很快）：

```bash
T="$LOCALAPPDATA/tauri"
# 1. 下载 NSIS 与 tauri 插件（SHA1 必须一致，CLI 会校验）
curl -L -o "$T/nsis-3.11.zip" https://github.com/tauri-apps/binary-releases/releases/download/nsis-3.11/nsis-3.11.zip
curl -L -o "$T/nsis_tauri_utils.dll" https://github.com/tauri-apps/nsis-tauri-utils/releases/download/nsis_tauri_utils-v0.5.3/nsis_tauri_utils.dll

# 2. 解压（zip 内目录上移一层）+ 放插件
python -c "import zipfile; zipfile.ZipFile(r'$T/nsis-3.11.zip').extractall(r'$T/NSIS_tmp')"
mv "$T/NSIS_tmp/nsis-3.11" "$T/NSIS"
mkdir -p "$T/NSIS/Plugins/x86-unicode/additional"
mv "$T/nsis_tauri_utils.dll" "$T/NSIS/Plugins/x86-unicode/additional/"

# 3. 重新 bun run build
```

### mpv 打包说明

`compile.ps1` 会自动检测 `src-tauri/assets/players/mpv/mpv.exe`，
不存在时从 GitHub 下载（可手动放置跳过）。mpv 随安装包分发，
是视频壁纸的默认高性能引擎（硬解、低占用）。

## 架构速览

```
前端 (Vite + React)                    Tauri/Rust
┌──────────────────────┐   invoke    ┌────────────────────────────┐
│ lib/client/api.ts     │ ──────────> │ src/commands.rs            │
│ lib/client/shell.ts   │ <---------- │   ↓ wallpaper-core (crate) │
│ 页面/组件             │   events    │ manager / mpv / library /  │
└──────────────────────┘             │ download / snapshot        │
                                     │   ↓ Win32                  │
                                     │ WorkerW 嵌入 / IDesktop... │
                                     └────────────────────────────┘
```

- **wallpaper-core**：无 UI 框架依赖的引擎 crate，可独立测试（`cargo test`）。
- **统一播放器抽象**（`wallpaper-core/src/player.rs`）：所有引擎通过
  `PlayerFactory`（创建/接管）+ `PlayerEngine`（load/暂停/音量/进度/快照/退出）
  两个 trait 接入，屏幕管理器只面向接口，不感知具体引擎。
  已有实现：`mpv.rs`（外部 mpv.exe + IPC，kind `"mpv"`，视频）、
  `src/internal_player.rs` 的内嵌 WebView 播放器（kind `"webview"`，视频）
  与 web 壁纸播放器（kind `"web"`，网页壁纸；复用切换时原地 `navigate`）。
- **内嵌播放器**：`player.html` 页面运行在隐藏窗口中，由 Rust 通过事件控制并
  SetParent 到 WorkerW；web 壁纸由 `WebPlayer` 引擎驱动 `web-*` 窗口直接加载 URL。
- **media 协议**：`http://media.localhost/<percent-encoded path>`，带 Range，
  只允许访问配置的媒体库目录与 tmp 目录。

## 启动模式：GUI 与 headless

应用单进程双模式（`src/cli.rs` + `src/lib.rs`）：

- **GUI（默认）**：启动屏 + 主窗口（按当前皮肤解析加载目标），关闭仅隐藏到托盘。
- **`--headless`**：零窗口全功能运行——壁纸播放、播放列表推进、下载、
  锁屏暂停、遮挡检测、系统事件全部照常（托盘保留）。
  任意时刻可通过 再次启动 exe / 托盘 / `livewallpaper4://` 深链 /
  控制管道 `ui.show` **按需创建主窗口**（`show_main_window`）。

要点：

- headless 下 tauri 事件循环照常运行，webview 播放器窗口本身就是隐藏创建的，
  因此 mpv / 内嵌 WebView / web 三种壁纸在 headless 下全部可用；
  `RunEvent::ExitRequested`（code = None，即窗口全关触发）被 `prevent_exit` 阻止，
  托盘退出（`app.exit(0)`）不受影响。
- 启动屏（splashscreen）从 `tauri.conf.json` 静态声明移到 Rust 创建
  （`build_splashscreen`），headless 不创建。
- 自启设置新增 `General.autoStartHeadless`：勾选后注册表 Run 命令行带 `--headless`。

### CLI（`src/cli.rs`）

```text
giantapp-wallpaper.exe --headless   # 无窗口运行
giantapp-wallpaper.exe status       # 播放状态摘要
giantapp-wallpaper.exe list         # 壁纸库列表（含序号）
giantapp-wallpaper.exe play 2       # 按序号播放（全部屏幕）
giantapp-wallpaper.exe pause|resume|stop|next|prev
giantapp-wallpaper.exe volume 50
giantapp-wallpaper.exe ui           # 唤起主窗口（无运行实例时启动应用）
giantapp-wallpaper.exe quit         # 按配置清理并退出
```

动词通过本地控制管道发给已运行的实例，执行完即退出；`ui` 连不上实例时回退为正常启动。
深链参数与未知首参不属于动词，按正常启动处理（单实例插件转发给既有实例）。

### 控制管道（`src/control.rs`）

`\\.\pipe\giantapp-wallpaper4`，所有启动模式都会启动，JSON-lines 协议：

```text
请求  {"id":1,"method":"pause_wallpaper","params":{}}
响应  {"id":1,"result":true}   /  {"id":1,"error":"..."}
事件  {"event":"playing-status-changed","data":null}
```

方法面 = 功能性 Tauri command 的镜像（`get_playing_status` / `show_wallpaper` /
`set_volume` / `get_config` / `set_config` / `get_download_status` / `get_mpv_status` …），
外加 `app_info` / `ui.show` / `app.quit`。纯 GUI 命令（文件夹选择对话框等）不暴露。
外部任何语言都能经命名管道驱动；这是 headless 模式的控制面。

### 事件枢纽（`src/events.rs`）

`EventHub`（tokio broadcast）：core 状态变化、下载进度、系统事件、配置联动等
统一 publish 到一条事件流，两个订阅者——Tauri emit（前端）与控制管道（CLI/脚本）。
新增事件时只需 `hub.publish(name, payload)`，两路自动可达。
注意：播放器窗口的点对点事件（`wp-cmd` / `wp-time`）不走 hub，保持直连。

### 如何新增一种播放器（web 播放器、exe 播放器等）

1. 实现 `PlayerFactory`：声明 `kind`（唯一标识，如 `"myweb"`）、`serves`
   （可服务的 `VideoPlayer` 设置值，需要新设置值时在 `models.rs` 的
   `VideoPlayer` 枚举追加；按壁纸类型路由的引擎如 web 播放器返回 `&[]`）、
   `is_available`（可用性，用于引擎兜底选择），
   以及 `create`（全新启动）与 `restore`（从快照接管仍在运行的实例，不支持可返回 Err）。
2. 实现一个 `PlayerEngine` 实例类：`load`（换源，支持则实现）、
   `attach_to_desktop`（把自己的窗口挂到桌面 WorkerW 层，参考
   `workerw::send_handle_to_desktop_bottom`）、暂停/音量/进度/探活，
   需要崩溃接管时实现 `snapshot`。
   媒体源 `MediaSource` 同时带本地 `path` 与应用内 `url`，引擎按需取用；
   网页类引擎用 `config.mouse_events` 决定鼠标事件是否穿透。
   参考实现：`src/internal_player.rs`（三种引擎均在）。
3. 注册工厂：UI 宿主类实现 `EngineHost::player_factories()` 返回你的工厂
   （内嵌 WebView 播放器、web 壁纸播放器即由此注入）；或在 `WallpaperApi::init` 处追加。
   注册顺序即兜底优先级：用户设置的首选引擎不可用时，按顺序退到下一个可用引擎；
   按壁纸类型路由的引擎（`serves` 为空）由管理器按 kind 直取，不参与视频兜底。

## 皮肤系统

见 **[3.皮肤系统.md](./3.皮肤系统.md)**。速览：皮肤是 `skins/<id>/` 下的一个
文件夹（`skin.json` 清单 + 任意技术栈的静态前端），`app` 型经
`http://skin.localhost/<id>/<entry>` 完整替换主窗口界面，`style` 型注入 CSS；
清单非法或入口缺失一律回退内置默认皮肤。皮肤与默认 UI 同权 invoke + 事件，
SDK 经 `/_sdk/client.js` 提供（源码 `src/client-sdk/`，产物
`src-tauri/src/generated/client-sdk.js` 随源码入库，`bun run build:sdk` 重新生成）。

## 编写规范（继承 v3）

- 每个文件尽量只做单一可靠的事情，做好以后就不要频繁修改。有一个简单的标准可以评判：
  假如5年后的你来看刚写的这部分代码，是否会觉得麻烦，摸不着头脑，如果是就简化它。
- 接口定义应该简单，不需要包罗万象，只处理程序需要的场景。

## 与 v3 的兼容性

- 配置 / 快照自动从 `%LOCALAPPDATA%\LiveWallpaper3` 一次性导入（v3 仍在时只读不写）。
- 壁纸元数据格式（`.metadata/*.meta.json` / `*.setting.json`）与 v3 一致，媒体库目录可直接复用。
- 深链协议为 `livewallpaper4://`。
- JSON 字段名保持 v3 约定（含 `authorID`、`IsCanceled` 历史命名），Hub 页面无感迁移。
