# 让所有皮肤都支持热加载

## 现状结论

热加载基础设施已存在并已提交(`skin_watch.rs`,commit 2eff9dbc):监听 `%LOCALAPPDATA%/LiveWallpaper4/skins/` 下所有皮肤目录(含 junction),500ms 防抖后——任何变化广播 `skins-changed`;当前生效皮肤变化广播 `refresh-page`。但刷新动作依赖**皮肤侧主动配合**:

- 7 个示例皮肤都在引导代码里显式调用 `api.initEvents()`(订阅 refresh-page → `location.reload()`),所以它们能热加载;
- **不含 SDK 或未调 `initEvents()` 的皮肤不会刷新**(第三方皮肤无法保证);
- **`skin.json` 的 `type`/`entry` 变更不生效**——窗口 URL 建窗时已解析,页面 reload 只是重载旧 URL;
- default 内置皮肤被显式排除(dev 模式走 Vite HMR,生产环境内置资源不可变,保持现状)。

## 改动内容(全部小改动,不引入新依赖)

### 1. 后端兜底整页刷新 — `src-tauri/src/skin_watch.rs` `handle_events`(L79-92)

当前生效皮肤文件变化时,在广播 `refresh-page` 之外,直接对主窗口 webview 执行 `eval("location.reload()")`(`app.get_webview("main")`,参照 lib.rs:879 既有 eval 用法)。热加载从此是后端保证,不依赖任何皮肤侧代码。事件照常广播(hub_compat v3 桥、skin-dev 面板仍依赖它)。双重触发 reload 无害(页面只卸载一次)。

### 2. `skin.json` 变更自动重新应用 — `skin_watch.rs`

检测一批事件中含当前生效皮肤的 `skin.json` 时:
- 解析新清单失效 → 调 `crate::recreate_main_window(app)`(回退 default,符合现有"永不白屏"约定);
- 清单有效 → 用 `main_window_navigate_url(app, &target)` 与当前 webview URL 比较:目标变了(type/entry 变更)→ `recreate_main_window`(内部优先原地 navigate,无闪烁);目标没变(仅改 name/version 等)→ 走普通 reload。

新增纯函数判定 + 单测。

### 3. SDK 自动订阅刷新 — `src/giantapp-wallpaper-ui/src/client-sdk/index.ts`

SDK 加载即自动 `listen("refresh-page", () => location.reload())`,第三方皮肤引入 `/_sdk/client.js` 后**零代码获得热加载**(也覆盖壁纸配置变更等其他 refresh-page 场景)。示例皮肤的显式 `initEvents()` 调用保持兼容,重复注册无副作用。改完需重新构建 SDK 产物(`src-tauri/src/generated/client-sdk.js`)。

### 4. 文档更新 — `docs/3.皮肤系统.md` 热更新章节(L137-160)

改为:所有皮肤(含不含 SDK 的)文件变化自动刷新;`skin.json` 的 `type`/`entry` 变更也会自动重新应用;皮肤无需再显式调用 `initEvents()` 才能热加载(仍推荐调用以获取其他事件)。

## 不做的事(边界)

- default 内置皮肤:维持排除(生产环境内置资源不可变,dev 走 Vite HMR);
- Web 型壁纸窗口(非皮肤,`internal_player.rs` 体系):不在本次范围。

## 验证

1. `cargo test`(skin_watch 模块:现有 3 个测试 + 新增 skin.json 判定测试,Windows junction 端到端测试覆盖);
2. 手动链路:`scripts/link-skin.sh examples/skin-dev` → 应用该皮肤 → 改 `style.css` 观察自动刷新(日志 `skin watch: skin ... changed`)→ 改 `skin.json` 的 `entry` 观察原地 navigate;
3. 前端 `bun build` SDK 产物后确认 `generated/client-sdk.js` 更新。
