# 皮肤热更新开发支持

## 目标效果
仓库里改 `examples/skin-dev/` 任何文件 → 正在运行的应用自动刷新显示新内容，零拷贝、零手动操作。

## 方案组成（三件事）

### 1. 目录联接（零代码，打通文件位置）
创建 junction：`%LOCALAPPDATA%\LiveWallpaper4\skins\dev` → `E:\codes\GiantappMan\livewallpaper\examples\skin-dev`（Windows 目录联接，无需管理员权限）。
- 实施时直接帮你建好（`cmd /c mklink /J`）
- 新增 `scripts/link-skin.sh`：通用脚本，参数为皮肤目录（如 `examples/skin-dev`），从 skin.json 读 `id` 作为链接名，已存在同名目录时提示不覆盖。方便以后给其他皮肤复用。

### 2. Rust 文件监听 + 自动刷新（核心）
- `src-tauri/Cargo.toml` 新增依赖：`notify` + `notify-debouncer-mini`（版本实施时用 cargo add 取最新兼容版）
- 新模块 `src-tauri/src/skin_watch.rs`：
  - `start(app: AppHandle)`：确保 `skins/` 目录存在，递归监听它；事件经 debounce（约 500ms，吸收编辑器原子保存的多次触发）后统一处理
  - 处理逻辑（决策部分抽成纯函数便于测试）：
    - 从变化路径提取皮肤 id（`skins/` 下第一段目录名）
    - 变化包含**当前生效皮肤**（`skin::configured_skin_id`）→ `publish_event(app, "refresh-page", ())` → 前端/皮肤 SDK 已内置 `location.reload()`，协议 no-cache 实时读盘，刷新即新内容。app 型和 style 型皮肤都覆盖
    - 同时发新事件 `skins-changed`（任何变化都发）
  - watcher 线程崩溃只 log::warn，不影响主程序
- `lib.rs` setup 中启动（系统事件启动处旁边，约 lib.rs:443）；headless 模式下监听照常、无窗口时事件无订阅者，安全

### 3. 设置页皮肤列表自动刷新（小改动）
- `src/giantapp-wallpaper-ui/src/pages/settings/appearance.tsx`：mount 时 `listen("skins-changed", fetchSkins)`（页面级 listen 有 downloads.tsx 先例）
- `examples/skin-dev/panels/events.js`：事件订阅列表加入 `skins-changed`，保持事件流面板与契约一致

### 文档
- `docs/3.皮肤系统.md` 新增「开发与热更新」小节：junction 脚本用法、watcher 行为（当前皮肤变化自动整页刷新、列表变化自动刷新设置页）、**已知边界：改 skin.json 的 `type`/`entry` 后需在设置页重新应用皮肤**（窗口 URL 是建窗时解析的）
- `docs/2.更新记录.md` 加条目

## 不采用的备选
- dev server / Vite HMR：需要给皮肤清单加 devUrl 并放通外部 URL 加载，改动协议安全模型，收益不成比例；`refresh-page` 整页刷新对静态皮肤已够快（本地读盘毫秒级）
- 变化时 `recreate_main_window`：比整页 reload 重得多，只在切皮肤时才需要

## 验证
1. `cargo test`：skin_watch 纯函数内联测试（id 提取、是否当前皮肤判断）+ 既有 skin.rs 测试不回归
2. 手动链路：建好 junction → 启动应用应用 Dev 皮肤 → 改 `style.css`/某个面板 js 保存 → 观察窗口 1 秒内自动刷新；往 `skins/` 放一个新皮肤文件夹 → 设置页列表自动出现
3. `bun run check`（如含格式/lint）确保无回归

## 交付后你得到的开发流
`scripts/link-skin.sh examples/skin-dev`（一次性）→ 之后编辑器里改皮肤文件，应用自动刷新，和改普通前端代码一样。
