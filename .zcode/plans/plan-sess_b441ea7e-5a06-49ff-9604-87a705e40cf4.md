# Headless 化 + 完全自定义皮肤系统 实施计划

## 已确认的形态

- **Headless**：单进程按需窗口。`--headless` 启动时零窗口（保留托盘），全部功能照常运行；之后通过再次启动 exe / 托盘 / 深链 / 控制管道按需创建主窗口。
- **皮肤**：皮肤包 = 数据目录下的文件夹（`skin.json` 清单 + 任意技术栈的完整前端），可完全替换整个界面。默认皮肤 = 现有 React 应用。额外支持 `style` 型皮肤（仅 CSS 覆盖，成本极低）。

关键前提（探索已确认）：`wallpaper-core` 零 Tauri 依赖；40 个 command 均为薄透传；`InternalPlayerController` 的 webview 播放器窗口本身是隐藏创建的，headless 下 tauri 事件循环仍在运行，因此 **mpv / 内嵌 webview / web 三种壁纸在 headless 模式下全部可用**。

---

## Phase 1 — Core 补齐（headless 就绪）

1. **`src-tauri/src/paths.rs`（新）**：从 `internal_player.rs::mpv_path()` 提取无 Tauri 的 mpv 路径探测（exe 同级 assets → 资源目录 → dev 树 → 已下载），`InternalPlayerController` 改为复用。
2. **`HeadlessHost`（放 `internal_player.rs` 或新 `headless_host.rs`）**：实现 `EngineHost`，仅提供 mpv 工厂路径 + default_cover，不注入 webview 工厂。 headless 模式下 webview 壁纸仍可用（按需创建隐藏窗口），故实际上两种模式都可继续用 `InternalPlayerController`；`HeadlessHost` 仅作为纯引擎模式的备用与测试件。
3. **core 小修**：`manager.rs::tick` 返回 `bool`（是否发生播放列表推进/遮挡切换），`api.rs::tick_once` 据此调用 `notify_change()`（修复现有缺口：内部推进不广播）。
4. **`mpv_download.rs` 解耦**：进度从 `AppHandle.emit` 改为回调注入 `on_event`；应用层把回调同时接到 Tauri emit 与控制管道广播。

## Phase 2 — 启动模式 + CLI + 控制管道

1. **`src-tauri/src/cli.rs`（新）**：argv 解析。首参为动词则走 CLI 客户端：`status / pause / resume / stop / next / prev / volume <n> / list / play <index> / ui / quit`；连接 `\\.\pipe\giantapp-wallpaper4`，打印 JSON 结果退出。`ui` 连不上管道时回退为正常启动 GUI。`--headless` 设置启动模式标志。
2. **`src-tauri/src/control.rs`（新）**：命名管道 JSON-lines 服务（所有模式都启动）：`{"id":1,"method":"status"}` → `{"id":1,"result":…}`；事件以 `{"event":"playing-status-changed","data":…}` 推送。方法表对齐功能性 command（排除纯 GUI：`show_folder_dialog`/`set_window_state` 等）。
3. **`src-tauri/src/events.rs`（新）**：`EventHub`（tokio broadcast）。现有各 `app.emit` 收敛为 hub 订阅转发：一份进 Tauri emit，一份进管道广播（`set_on_change`、下载回调、系统事件、`appearance-changed` 等）。
4. **`lib.rs` 改造**：
   - splashscreen 从 `tauri.conf.json` 静态声明移到 Rust 创建（仅 GUI 模式），headless 启动零窗口；
   - 主窗口创建逻辑抽成 `show_main_window(app)`（存在则 show+focus，不存在则按当前皮肤 URL 创建），单实例回调、托盘、深链、`ui` 命令都走它；
   - headless 模式在 `RunEvent::ExitRequested` 中 `prevent_exit()` 保活；
   - `ConfigGeneral` 增加 `auto_start_headless: bool`，开启自启时注册表命令行带 `--headless`（设置页加勾选项）。

## Phase 3 — 皮肤系统（Rust 侧）

1. **`src-tauri/src/skin.rs`（新）**：
   - 清单模型 `skin.json`：`{ id, name, version, author, type: "app"|"style", entry, compat: 4 }`；
   - 扫描 `%LOCALAPPDATA%/LiveWallpaper4/skins/*/`，校验清单与 entry 存在性；
   - 主窗口 URL 解析：默认皮肤 → `index.html`；app 型 → `skin://localhost/<id>/<entry>`；style 型 → `index.html` + 初始化脚本注入 `<link href="skin://localhost/<id>/<entry>">`；
   - 注册 `skin://` 协议：`_sdk/*` 特殊路径返回内置 SDK，其余静态文件服务（MIME 表复用 `media_protocol` 思路，防 `..` 路径穿越）；
   - **回退**：entry 缺失/清单非法 → 一律回退默认皮肤，保证永不白屏。
2. **新 command**：`list_skins` / `set_active_skin(id)` / `open_skins_folder`。`ConfigAppearance` 增加 `skin: String`（默认 `"default"`）；`set_config("Appearance")` 联动：皮肤变化时销毁并重建主窗口（复用几何恢复逻辑）。
3. **能力验证点**：`skin://` 属本地上下文，`main` 窗口的 `local-windows` capability 对其生效（invoke 可用）；hub/oauth/hub-detail 等后端托管窗口不受皮肤影响。

## Phase 4 — 皮肤系统（前端 + SDK）

1. **`client-sdk`**：以 `lib/client/api.ts` + `types.ts` + `shell.ts`（均无 React 依赖）为源，新增 esbuild/vite 二次构建产出 IIFE → 暴露 `window.WallpaperClient`（API 类 + 事件订阅 + 类型）。产物经 `include_str!` 编入二进制，由 `skin://_sdk/client.js` 提供；`bun build` 前置脚本生成（生成文件入库，避免编译顺序问题）。
2. **默认皮肤**：`appearance.tsx` 增加「皮肤」分区（列表：默认 + 已安装，含 name/version/author/type，应用按钮、打开皮肤文件夹、刷新）；`api.ts`/`types.ts` 增加对应封装与 `SkinInfo`。
3. 皮肤切换后广播 `appearance-changed`，皮肤自行决定刷新策略。

## Phase 5 — 示例皮肤 + 文档 + 验证

1. **`examples/skin-minimal/`**：最小可用 app 型皮肤（单 HTML + `/_sdk/client.js` 调用：壁纸列表、应用/暂停、音量、深色样式），复制进 skins 目录即可验证。
2. **文档**：新增 `docs/3.皮肤系统.md`（清单规范、SDK 用法、命令/事件契约、安装打包说明）；更新 `docs/1.开发.md`（headless 启动模式、CLI、管道协议、EventHub）。
3. **验证**：`bun run check` + `bun run test`（管道帧协议加单测）+ UI `tsc && vite build`；手工冒烟：`--headless` 起服务→`status`/`play`/`volume` 生效→`ui` 唤起窗口→切换皮肤→装无效皮肤验证回退→退出时 dispose 正常。

## 风险与注意

- tauri 零窗口保活：加 `ExitRequested::prevent_exit` 兜底（实施时验证）。
- `skin://` 能力上下文（local vs remote）在实施首日验证，若有出入改用 `register_asynchronous_uri_scheme_protocol` + capability 调整。
- 皮肤与现有 UI 同权调用 command（完全自定义的代价）：视为用户自装内容，与 exe 型壁纸同级信任模型，文档明示。
- 现有行为零回归：默认皮肤路径、单实例、深链、托盘、hub 兼容脚本全部保留原语义。
